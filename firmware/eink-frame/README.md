# E-ink frame firmware

PlatformIO / Arduino firmware for the e-ink gift frames: a DFRobot FireBeetle 2 ESP32-E driving a Waveshare 7.5" V2 panel (800×480, black and white) through a Good Display DESPI-C02 adapter. Build notes, the parts list and the printed case are on the site page (`content/docs/miscellany/eink-gift-frames.md`); the API it calls is `workers/eink-frame/`.

## What it does

Each wake (everything runs in `setup()`; it never reaches `loop()`):

1. Reads the battery. Below 3.3 V it shows a "time for a charge" screen and checks again every 2 hours.
2. Joins the saved Wi-Fi (15 s timeout).
   - No saved network, or two failed wakes in a row: it shows setup instructions and opens a hotspot named `Poem-Frame-XXXX` for 5 minutes (WiFiManager captive portal). The recipient picks their Wi-Fi there. The portal also has a "Frame code" field holding the token, in case it ever needs re-entering.
3. `GET https://www.extra-ransom.net/api/eink/frame` with `X-Token`, `X-Battery-mV`, `X-RSSI` and `X-FW` headers. HTTPS is verified against the root CAs in `include/roots.h`.
4. Draws the header (weather icon, high/low, conditions and rain chance, date, place), the body (poem or message, at the largest font that fits) and the footer (time of the update, battery gauge, "please charge me" below 3.5 V). Then it puts the panel to sleep, which keeps the image with no power.
5. Deep-sleeps for the `sleep_s` the server returned (it lands on the next refresh time; default 06:00 and 17:00 local).

If it can't reach the server it leaves the old picture up and retries after 1, 2, 4 and then 6 hours. If the server returns 401 (no token, or the frame was deleted in the admin page) it shows "This frame isn't registered yet" and the frame's 4-character ID.

## Wiring (FireBeetle 2 ESP32-E GPIO → DESPI-C02)

| DESPI-C02 | ESP32 GPIO | Notes |
|---|---|---|
| 3.3V | 3V3 | |
| GND | GND | |
| SDI (DIN) | 23 | VSPI MOSI |
| SCK (CLK) | 18 | VSPI SCK |
| CS | 14 | |
| D/C | 13 | |
| RES (RST) | 26 | |
| BUSY | 25 | input |

The pins are GPIO numbers. Check DFRobot's FireBeetle 2 ESP32-E pinout for the silkscreen label of each pad, and change `include/config.h` if you wire differently. The panel's 24-pin ribbon plugs into the adapter's FPC connector with the contacts facing the latch. Set the adapter's RESE switch to the value Good Display lists for the 7.5″ 800×480 (UC8179 / GDEW075T7-class) panel.

Battery: the LiPo plugs into the FireBeetle's PH2.0 socket. **Check polarity first; cheap cells are often wired the opposite way.** The board reads half the battery voltage through a 2× 1 MΩ divider. Most sources put it on GPIO34 (A2): verify that before trusting the gauge (`PIN_BATTERY_ADC` in `config.h`; `-1` turns it off). For the lowest sleep current, cut the FireBeetle's low-power pad as DFRobot describes, which disables the power LED.

## Build and flash

```bash
cd firmware/eink-frame
# get the token from https://www.extra-ransom.net/api/eink/admin after adding the frame there
EINK_TOKEN=abcd1234... pio run -t upload
pio device monitor          # 115200 baud: battery, HTTP status, sleep time
```

The token is compiled in and copied to flash (NVS) on first boot. After that, re-flashing with a different `EINK_TOKEN` won't override it; erase first (`pio run -t erase`) or change it through the setup portal. Wi-Fi credentials live in the ESP32's own Wi-Fi storage and survive re-flashing.

## Files

- `src/main.cpp`: wake, Wi-Fi, fetch, sleep logic.
- `src/render.cpp`: layout, word wrap, font ladders, weather icons (drawn with shapes, no bitmaps). Fonts are u8g2 Latin-1 (`_tf`), which is why the worker rewrites curly quotes and dashes.
- `include/config.h`: pins, API URL, battery thresholds, timeouts.
- `include/roots.h`: generated by `tools/make_roots.sh` (macOS) from the system roots for Google Trust Services, GlobalSign, Let's Encrypt and SSL.com, the CAs Cloudflare issues from. The earliest expiry is GlobalSign Root CA in January 2028, and GTS Root R4 (the current chain's root) runs to 2036. Re-run and re-flash if Cloudflare ever moves to a CA outside that list. The ESP32 core doesn't check certificate dates, so the frame needs no clock.

## Power budget (estimate, not measured)

Each wake is roughly 5–8 s of Wi-Fi plus TLS at ~100 mA, plus a ~4 s full refresh at ~30 mA: about 0.2–0.3 mAh. Two wakes a day plus deep sleep at a few tens of µA comes to about 1–2 mAh/day, so a 2000 mAh cell should go many months between charges. Measure a real frame's sleep current (inline meter on the battery lead) before promising anyone a number.
