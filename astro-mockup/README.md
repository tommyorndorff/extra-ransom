# extra-ransom: Astro + Starlight mockup

This directory is a mockup of the site in Astro + Starlight, built from the same Markdown that the Hugo site uses. It exists to compare the two stacks at real size (navigation, search, build, authoring) before anyone decides to migrate. The Hugo site is the one that ships. Its content, `config.yaml`, `.github/workflows/workflow.yml` and the S3 and CloudFront deploy are not changed by this mockup.

## Run it

Requires Node 22. On the machine this was built on, the zsh nvm lazy-load hook was broken, so Node was called directly from `~/.nvm/versions/node/v22.23.1/bin`. Use whatever Node 22 is on your PATH.

```bash
cd astro-mockup
npm install
npm run convert   # regenerate src/content/docs/docs/ from ../content/docs (idempotent)
npm run dev       # local dev server
npm run build     # production build to dist/ (includes link validation and Pagefind)
npm run preview   # serve dist/ locally
```

`npm run convert` must be re-run whenever the Hugo content changes. The generated files under `src/content/docs/docs/` are build input, not source; edit the Hugo files under `../content/docs/` instead.

## Design

**URLs are preserved.** Content is mirrored to `src/content/docs/docs/<section>/…`, so pages serve at `/docs/<section>/<page>/` exactly as they do under Hugo. Absolute `/docs/…` links and `/static/<topic>/…` asset links therefore work without rewriting.

`scripts/convert.mjs` does the following:

- Renames `_index.md` to `index.md`.
- Maps `weight` to `sidebar.order` (and keeps `weight`). Keeps `title`, `date`, `draft`. Other front-matter keys are dropped with a warning.
- Collects `aliases` into `src/redirects.json` (alias to canonical URL), which `astro.config.mjs` loads into Astro's `redirects`. Aliases that collide with a real page are dropped.
- Renders each ```` ```goat ```` block to SVG with the `goat` binary (PATH first, then `node_modules/.goat/goat`, installed with `go install github.com/blampe/goat/cmd/goat@latest`) into `public/goat/<page>-<n>.svg`, and replaces the block with an image. If no binary is found, the block becomes a plain `text` block.
- Strips a leading `# H1` that duplicates the front-matter title, since Starlight renders the title itself.
- Rewrites relative Markdown and `href` links to absolute `/docs/…/` form, resolved against the page's own URL. Fenced code is left alone.
- Warns on Hugo shortcodes and dropped front-matter keys.

**Static assets** are linked into `public/` rather than copied: `public/static` points at `../../static/static`, and each standalone page (`warbirds`, `salamanders`, `frame-calc`, `couch-to-5k`, `norway`) points at `../../static/<dir>`. Standalone pages are served verbatim and are not Starlight content.

**Link validation.** `starlight-links-validator` runs at build time. Standalone pages and assets (`/warbirds/**`, `/salamanders/**`, `/couch-to-5k/**`, `/norway/**`, `/frame-calc/**`, `/static/**`, `/goat/**`) are excluded because they are not Starlight pages.

**Home page and styling.** The home page is `src/content/docs/index.mdx` (splash template). `src/styles/custom.css` ports the Hextra palette, fonts and hero gradient, and keeps drawings on white in dark mode. Tables scroll horizontally on small screens.

**Sidebar.** One autogenerated group per section, in `menu.main` order. `equipment.md` is mirrored with `draft: true` and is not in the sidebar.

## Hugo vs Astro (measured, rough)

Single warm runs on the same machine. Treat these as indicative, not a benchmark.

| | Hugo (`hugo --minify`) | Astro (`npm run build`) |
|---|---|---|
| Pages built (`docs/**/index.html`) | 88 | 88 |
| Build time | ~0.64 s | ~2.85 s |
| Output size | 55 MB | 56 MB |
| Build includes | Hugo only | Pagefind index and link validation |
| Search | Not compared here (Hextra's search was not checked) | Starlight's built-in Pagefind (not yet checked in a browser) |

Takeaway: at this scale size and speed are a wash. Astro's build is slower, but it does more work (link validation and a search index). Any real benefit of the move would be in authoring and ecosystem, not build performance. That has not been demonstrated here.

## Not verified / known gaps

- **Visual checks not done.** Home-page cards, dark mode, the hero gradient and the `<details>` page have not been compared against the Hugo site. The hero styling was written from Starlight's source, not checked by eye.
- **Browser checks not done.** Pagefind search results (e.g. "Garrison"), redirect navigation from alias URLs, and `/frame-calc/` and `/salamanders/` loading have not been exercised in a browser.
- **Equipment page** is a draft, so it is left out of the sidebar and the build.
- **`editLink`** points at the Hugo content paths (`content/`), not at `astro-mockup/`.
- **Build not re-run for this README.** The numbers above come from earlier runs.

## Open questions for a real cutover

1. **CI and deploy.** `workflow.yml` builds with Hugo and deploys with a two-pass `aws s3 sync` (1-year immutable cache for css/js/svg/img/fonts/ico, then `max-age=0` for html and the rest) and a CloudFront `/*` invalidation, plus the `gh-pages` mirror. An Astro build changes the build step, the output directory and possibly the cache rules.
2. **GoAT.** Keep GoAT (rendered to SVG at convert time, needs a Go toolchain in CI) or move the diagrams to hand-made SVG or Mermaid.
3. **Cache-busting.** Standalone pages use `?v=YYYYMMDD` query strings on their CSS and JS because of the immutable cache. Decide whether that convention carries over, since Astro's bundling may replace it for Starlight pages.
4. **Converter lifecycle.** Is `convert.mjs` a one-shot migration (then Hugo content is retired) or an ongoing bridge while both stacks exist? If ongoing, the Hugo source stays authoritative and the mirror stays generated.
5. **Shortcodes.** None are in use in the Markdown content. The only Hextra shortcodes are on `content/_index.md`, and those are replaced by the hand-written home page.
